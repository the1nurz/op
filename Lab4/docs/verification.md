# Перевірка Lab4

Дата перевірки: 17 листопада 2026 року.
Джерело вимог: `oop-practicum-simplified (3).pdf`, сторінки 14–16,
та уточнення користувача щодо еліпса без заповнення.

## Компіляція і запуск

Windows, CMake, GNU C++ 16.2.0 з `C:/msys64/ucrt64`, конфігурація Debug.
Зібрано `build/Lab4.exe` та три тестові програми. На фінальному складанні
не було повідомлень компілятора про помилки чи попередження.

Фактичний результат CTest:

```text

```

## Вимоги і спосіб перевірки

| Вимога | Реалізація та перевірка |
| --- | --- |
| Окремий проєкт Lab4 на основі Lab3 | Збережено структуру CMake, класи, обробники повідомлень і GDI-обгортки з Lab3. `git diff -- lab3` порожній. |
| Глобальний статичний редактор | `static MyEditor editor;` у `src/MainWindow.cpp`, поза класами та функціями. `new MyEditor` відсутній. |
| Статичний масив на 128 фігур | `Shape* pcshape[kCapacity]{}` з `kCapacity = 128`. Тест створив 128 фігур, відхилив 129-ту й очистив масив. Самі фігури створюються динамічно. |
| Інкапсуляція | Координати `Shape` та масив редактора приватні; доступ через методи. |
| Абстрактний клас і поліморфізм | `Shape::Show` — чисто віртуальний; редактор малює через `Shape*`. Статичні перевірки абстрактності та віртуального деструктора пройшли. |
| Множинне успадкування | `CircleLineShape` успадковує `LineShape` і `EllipseShape`; `CubeShape` — `LineShape` і `RectShape`. |
| Одна база Shape в складених фігурах | Три проміжні класи використовують `virtual public Shape`. Перевірено однозначне перетворення в `Shape*`; для лінії з кружечками адреси спільної бази однакові з обох гілок. |
| Повторне використання Show | Нові класи викликають кваліфіковані `LineShape::Show`, `EllipseShape::Show` або `RectShape::Show`. Власних викликів GDI-примітивів у них немає. |
| Усі шість фігур | Перевірено пікселі результатів малювання; кожну фігуру також створено мишею у запущеному Lab4. |
| Стиль прямокутника та еліпса | Чорне перо і `NULL_BRUSH`. Тест перевіряє незаповнену середину; різні напрямки введення прямокутника й еліпса пройшли. |
| Пунктир для всіх фігур | `PS_DOT` при `preview = true`. Для кожної з шести фігур прев'ю містить чорні пікселі та менше чорних пікселів, ніж суцільне зображення. |
| Шість кнопок, зображень і пунктів меню | `Lab4WindowSmoke` створює приховане вікно у власному процесі; перевіряє кількість кнопок, зображень та пунктів меню. |
| Підказки | Для кожного з шести ID тест надсилає `TTN_GETDISPINFOW` через `WM_NOTIFY` і перевіряє український текст. Це перевірка обробника, не часу появи popup-підказки. |
| Синхронізація вибору | Тест послідовно виконує шість `WM_COMMAND` і перевіряє єдину позначку меню та відповідну кнопку. У GUI перевірено вибір куба через Toolbar та еліпса через меню. |
| WM_PAINT | Порівняння пікселів при повторному малюванні пройшло. У GUI всі шість фігур збереглися після розгортання та відновлення розміру вікна. |
| Скасування та межі масиву | Перевірено відсутність подвійного Begin, скасування чернетки, скасування при зміні інструмента, некоректні ID та межу 128. |
| Ресурси GDI | Вибрані перо, пензель та режим фону після Show відновлюються. Після 500 циклів малювання всіх шести фігур кількість GDI-об'єктів не збільшилася. |
| Пам'ять | `Clear` і деструктор видаляють чернетку та кожний об'єкт через віртуальний деструктор. Тести створення, скасування й очищення пройшли; окремий профайлер купи не застосовувався. |
| Звіт і UML | Додано редаговані Markdown та HTML з повними джерелами, UML, реальними скріншотами, висновками та всіма шістьма відповідями. |

## Межі перевірки

MSVC та Visual Studio в цьому середовищі не встановлені. Тут підтверджено
складання і запуск Windows-програми MinGW; складання у Visual Studio потрібно
окремо виконати за README. Тести підказок перевіряють усі тексти й обробник;
фактичний час появи підказки при наведенні миші варто перевірити вручну.

Звіт збережено в редагованих Markdown та HTML. Для здачі саме у DOCX можна
відкрити HTML у Word і зберегти в потрібному форматі. Дані титульного аркуша
взято зі звіту Lab3.
