# Лабораторна робота №2
Тема: розробка графічного редактора об'єктів. Мета: засвоїти інкапсуляцію, абстрактні класи, успадкування та поліморфізм у C++.

## Варіант 27
- 27 mod 3 = 0: динамічний масив `Shape** pcshape`, N = 127.
- 27 mod 4 = 3: чорний пунктирний гумовий слід.
- 27 mod 2 = 1: прямокутник задається від центра до кута; еліпс — протилежними кутами охоплюючого прямокутника; інструмент показано в заголовку.
- 27 mod 5 = 2: прямокутник має чорний контур та заповнення, еліпс — чорний контур без заповнення.
- 27 mod 6 = 3: заповнення прямокутника рожеве, RGB(255,192,203).

## Файли і класи
`main.cpp` — меню, цикл повідомлень, введення мишею, масив і перерисовування.
`Shape.h/.cpp` — абстрактний клас із координатами, SetEnd, чисто віртуальним Draw та віртуальним деструктором.
`PointShape`, `LineShape`, `RectShape`, `EllipseShape` (кожен у власних .h/.cpp) — крапка, лінія, прямокутник, еліпс.
`CMakeLists.txt` — збірка; `tests/smoke.cpp` — одна інтеграційна перевірка.
`REPORT.md`, `DEFENSE.md`, `class_diagram.md` — матеріали звіту і захисту.
[Готовий DOCX](Звіт/Звіт_Лабораторна_2.docx) оформлено за Lab1; оригінал Lab1 не змінено.

## Збирання і запуск у Windows
Потрібні CMake 3.20+ і компілятор C++17: Visual Studio 2022 з компонентами C++ або MinGW-w64.

Visual Studio:
```powershell
cmake -S lab2 -B lab2/build -G "Visual Studio 17 2022" -A x64
cmake --build lab2/build --config Debug
.\lab2\build\Debug\Lab2.exe
```
MinGW (каталог bin має бути в PATH):
```powershell
cmake -S lab2 -B lab2/build -G "MinGW Makefiles"
cmake --build lab2/build
.\lab2\build\Lab2.exe
```
У VS Code відкрийте папку lab2, установіть розширення CMake Tools, оберіть комплект компілятора, виконайте CMake: Configure, CMake: Build, CMake: Run Without Debugging.

## Користування
Меню має порядок «Файл | Об'єкти | Довідка». В «Об'єкти» оберіть інструмент. Натисніть ліву кнопку на полотні й перетягніть мишу. Під час введення видно чорний пунктир; відпускання кнопки зберігає фігуру. Крапка позначається невеликим хрестиком у місці натискання. Для прямокутника натискання задає центр, для еліпса — кут охоплюючого прямокутника. Esc або втрата захоплення миші скасовує чернетку. Усі завершені об'єкти повторно малюються в WM_PAINT. Файл → Вихід закриває програму. На диску рисунок не зберігається; після закриття об'єкти видаляються.

## Перевірка
```powershell
cmake -S lab2 -B lab2/build -DLAB2_BUILD_TESTS=ON
cmake --build lab2/build --config Debug
ctest --test-dir lab2/build -C Debug --output-on-failure
```
Фактично виконано збірку GCC 16.2.0 (MinGW, Windows) та CTest: 1/1 успішно. Тест викликає справжню віконну процедуру через повідомлення, перевіряє меню й заголовок, створення чотирьох фігур, GDI-пікселі рожевого прямокутника, незаповнений еліпс, пунктир, Esc, межу 127 та очищення. Діалог попередження в тесті замінено лічильником викликів, щоб не блокувати тест. Виклик Draw обробником WM_PAINT перевірено пробним класом; візуальне відновлення після згортання та зміни розміру додатково перевірено через GUI. У незалежному прогоні відстежено 129 C++-виділень пам’яті, після завершення залишилося 0 активних. Після 34 000 повторних Draw лічильник GDI дорівнював 6 → 6. Перевірка охоплює звичайне введення, скасування і закриття.
Окремо запущено графічний редактор, перевірено чотири інструменти й отримано реальні скріншоти. Параметри звірено зі сторінками 7–11 `oop-practicum-simplified (4).pdf`. П’ять контрольних запитань із відповідями є в DEFENSE.md та DOCX. Повний протокол перевірки наведено в [AUDIT.md](AUDIT.md).
