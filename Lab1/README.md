# Lab1 — C++ / WinAPI, варіант 27

В1 = 27 mod 4 = 3: вибір групи зі списку. В2 = 28 mod 4 = 0: введення тексту.
Обидва результати з'являються у головному вікні після натискання «Так».
«Відміна», Esc та хрестик закривають діалог без зміни результату.
Enter підтверджує введення; Tab переміщує фокус між елементами.
Кнопка «Так» у списку недоступна, доки не вибрана група.

Діалоги немодальні: головне меню доступне, коли відкритий діалог.
Вибір наступної роботи автоматично закриває попередній діалог.
Закриття головного вікна закриває діалог і завершує програму.
Текст підтримує Unicode, пробіли та символ `&`, ліміт — 4096 символів.

## Структура

- `main.cpp`: реєстрація та створення головного вікна, меню, цикл повідомлень,
  керування активним діалогом та відображення результату.
- `module1.cpp/.h` та `module1.rc`, `module1_resources.h`: лише діалог вибору групи.
- `module2.cpp/.h` та `module2.rc`, `module2_resources.h`: лише діалог введення тексту.
- `dialog_result.h`: спільний тип callback для передавання результатів головному вікну.
- `resource.h/.rc`: лише головне меню.
- `CMakeLists.txt`: створює Windows GUI executable `Lab1`.

Callback-функції діалогів приховані в анонімних namespace. Модулі не включають
один одного. Ресурси діалогів залишаються у відповідних модулях, а не у спільному
`resource.rc`. Діалоги створюються через `CreateDialogParamW`, закриваються через
`DestroyWindow`; `IsDialogMessageW` забезпечує клавіатурну навігацію.

У список автоматично додаються декілька груп ФІОТ: ІО-41, ІО-42, ІО-43,
ІП-41, ІП-42, ІС-41, ІС-42. Це не повний перелік факультету.
Назви можна змінити в масиві `Groups` у `module1.cpp`.

## Збирання на Windows

У підготовленому локальному workspace є переносні CMake та GCC у `Lab1/.tools`,
а готова програма — `Lab1/build-mingw/Lab1.exe`. Ці папки не входять до Git-репозиторію.
Якщо використовуєте цей локальний workspace, з його кореня виконайте:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Lab1\build.ps1
& .\Lab1\build-mingw\Lab1.exe
```

Скрипт використовує наявні переносні інструменти та тимчасово додає їх до PATH тільки
для процесу збирання. Якщо перенести лише вихідні файли без `.tools`, він
використає встановлені CMake та Visual Studio 2022.
Джерела переносних інструментів: [CMake](https://cmake.org/download/) та
[w64devkit](https://github.com/skeeto/w64devkit/releases).

### Збирання встановленими інструментами

Потрібні **CMake 3.20+** та **Visual Studio 2022 / Build Tools 2022** з компонентом
«Desktop development with C++» (MSVC та Windows SDK).
Після встановлення інструментів перезапустіть VS Code, щоб оновився PATH.

З термінала PowerShell у корені workspace:

```powershell
cmake -S .\Lab1 -B .\Lab1\build -G "Visual Studio 17 2022" -A x64
cmake --build .\Lab1\build --config Release
& .\Lab1\build\Release\Lab1.exe
```

Альтернатива, якщо встановлено MinGW-w64 (g++, windres, mingw32-make) та CMake
і всі ці інструменти доступні в PATH:

```powershell
cmake -S .\Lab1 -B .\Lab1\build-mingw -G "MinGW Makefiles" -DCMAKE_BUILD_TYPE=Release
cmake --build .\Lab1\build-mingw
& .\Lab1\build-mingw\Lab1.exe
```

## Перевірка роботи

Проєкт перевірено локально: зібрано GCC через CMake без попереджень. Автоматичний тест
`tests/smoke.cpp` перевірив реальні ресурси та обробники WinAPI: заповнення списку,
стан кнопки підтвердження, вибір групи, Unicode-текст, скасування, порожній рядок,
перемикання між діалогами, 20 повторних відкриттів і завершення програми.
Усі перевірки пройдено. Зібраний EXE залежить лише від системних DLL Windows.

Додатковий тестовий target увімкнено у підготовленій локальній папці збирання. Запуск:

```powershell
& .\Lab1\build-mingw\Lab1Smoke.exe
```

Для іншої папки збирання додайте `-DLAB1_BUILD_TESTS=ON` до команди конфігурації
CMake. Тест короткочасно відкриває діалоги і сам закриває їх. Навігацію клавішами
та вигляд вікон перевірте вручну:

1. Виберіть «Робота1»: список заповнений, «Так» вимкнено.
2. Виберіть ІО-42 і натисніть «Так»: діалог закрито, головне вікно показує групу.
3. Виберіть «Робота2», введіть `Привіт, ФІОТ! & 27` і натисніть Enter:
   головне вікно показує введений рядок без змін.
4. Змініть введення та натисніть «Відміна»: попередній результат збережено.
5. Перевірте Esc, хрестик та підтвердження порожнього рядка.
6. Відкрийте «Робота1», потім через меню «Робота2»: перший діалог закривається.
7. Повторіть відкриття обох діалогів кілька разів. Закрийте головне вікно з
   відкритим діалогом: програма завершується повністю.
